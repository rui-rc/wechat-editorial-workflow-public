# 规则先行的制作步骤

适用于没有现成模板、需要自行设计的稿件。两个视觉参考只是规则的例子；不需要先积累大量案例，也不要求用户选择技术路线。按以下顺序推进，已有明确要求直接采用。

## 1. 列清本篇的边界

执行者在任务记录中写清：当前机构规范；不能改的事实和文字；用户指定的素材／效果；允许自行决定的部分。没有依据的品牌、数字、姓名不填造。缺项只影响某个部分时，继续其他部分。

输出是一份简短制作依据，不是发给用户填写的问卷。

## 2. 把风格要求转成设计决定

先回答“读者最先应该注意什么”，选一个主要视觉中心，再确定辅助信息与正文的层级。

| 当前目标 | 可以推导的操作 | 不应机械推导 |
|---|---|---|
| 突出纪念事件 | 让已确认的周年／日期与主标题组成重点区，次要信息降低分量 | 任何纪念稿都加巨大数字或同一套红金模板 |
| 突出个人表达 | 把标题、作者身份和引言连成阅读顺序，少量强调关键句 | 第一人称文章必须采用来信风格 |
| 庄重 | 稳定对齐、清楚层级、克制的装饰与重复样式 | 一定使用深红底、大量徽章或整段红字 |
| 亲近、有人感 | 让作者与具体表达更可见，减少无关装饰 | 牺牲事实、机构规范，或编造个人经历 |

具体构图方法见 [视觉方向](visual-direction.md)。方向有明显分歧且会改变整篇效果时才做短样确认；否则由执行者选定并继续。

## 3. 先搭内容骨架，再安排视觉积木

按当前要求组织：必要品牌 → 主视觉／标题 → 辅助信息与引言 → 章节与正文 → 必要尾部。顺序服从本篇规范，不强制所有账号都有首尾图、编号或固定审核层级。

将内容放进合适的积木：
- **文字组**：标题、年份、作者、说明，利用字号层级、粗细和对齐建立主次。
- **背景区**：集中强调一个重点；之后的章节只作轻量呼应，不每段重复大色块。
- **边框／分隔线**：分组和章节边界，不承担需要复杂定位的网页布局。
- **留白**：分清同组与跨组关系；正文硬性间距不能擅自修改。
- **图片／动态／交互**：确实帮助表达时使用，先核对来源、用途和阅读方式。

先决定主色、辅助色和正文颜色的分工，再选具体色值；已有品牌与指定颜色优先。章节采用同族规则，允许按内容调整，不固定篇章数量。

## 4. 选择实现路径

- 平面文字、背景、边线、简单图片：按 [HTML兼容路径](html-compatibility.md) 自行组合，不必有对应模板。
- 用户指定原生素材，或需要多列、横滑、点击、复杂动效：按 [原生卡片](native-cards.md) 在同一浏览器操作，保留原有结构。
- 部分现成素材合适：基础稿与原生组件结合；先完成基础导入，插入原生组件后不再整篇覆盖。
- 已认可旧稿且适合本篇：备份或复制后局部更新，仍检查真实文字长度。

## 5. 写入内容并先做源文件检查

文字内容与角色必须从材料和制作依据生成，不能从错误成品倒推一份“正确清单”。自制HTML先运行预检，按报告修正；超出保守路径的效果由执行者决定换原生结构或只验证相关模块。

复用参考模块时填写占位项；不适用的辅助信息直接移除。两个现有模块不是能力上限，允许按同一规则生成新的排列。

## 6. 导入、保存并核对目标效果

沿用当前浏览器实例与会话。核对四项：内容完整、实际规范、视觉意图、可编辑与持久化。只检查最容易出问题的属性和长内容，不为已验证的普通属性重复开展大规模试验。

已知路径正常运行也要保存复开和看窄屏，这是每篇的交付检查；新结构、新效果或版本变化才需要针对性小试验。两者都不是要求用户积累训练数据。

## 7. 局部修复或有依据地换路

按兼容指引中的故障表处理。技术问题由执行者解决；只有关键事实、要求冲突、明确指定效果无法保留、付费或对外发布等需要用户决策时才暂停相关部分。

完成的标准是本篇目标得到实现。模板数量、日志成功或案例数量都不替代成品判断。
