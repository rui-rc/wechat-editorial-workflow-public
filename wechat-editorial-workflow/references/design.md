# 风格、素材与制作路线

先按 [视觉方向与设计](visual-direction.md) 把本篇意图转成主视觉、信息层次和素材用途，再选择制作路线。技术可用性和审美效果分别验证。

## 先识别用户偏好

开始选材和排版前，先检查用户是否已经提供：
- 想要的风格、配色、疏密、正式或活泼程度，以及不喜欢的效果；
- 参考推文、截图、旧稿或希望沿用的模板；
- 指定必须使用的图片、动图、秀米素材、组件或具体版式；
- 时间要求，以及希望严格复现、局部借鉴还是由执行者自由设计。

已有信息直接采用，不重复问。缺少偏好且会影响设计方向时，可用一句话询问“有没有想沿用的风格、参考推文，或必须使用的素材和版式？”；用户明确没有偏好或授权自主设计时直接推进，不强制问卷。未答复不代表认可某个风格。
区分必须使用、优先采用和仅供参考。用户指定素材或版式时优先落实，不能因自己觉得另一套更好看而替换；指定不可访问、需付费、无法编辑或与学院硬规范冲突时，指出具体影响并给出局部适配或替代方案，不擅自购买或舍弃。明确的新要求按主技能的规则冲突处理方式执行。

## 根据材料选最快可行路线

| 情形 | 优先方式 |
|---|---|
| 有用户认可的同类旧稿 | 备份或复制后替换内容和照片，保留合适设计 |
| 有明确指定模板或相近的秀米模板 | 在模板副本里填稿，拆取适合元素并校正正文规范 |
| 只有部分合适素材 | 基础内容先导入，再在秀米组合标题、分隔线和图片组件 |
| 内容简单、时间紧 | 简洁图文，优先信息层次、照片和阅读连贯性 |
| 明确参考无法由现有模板满足 | 定制HTML或视觉素材，再导入并局部调整 |
| 需要滑动或点击互动 | 优先使用秀米原生组件，实际预览验证 |

允许混用。先复用合适成熟设计，再考虑组合或定制。不能为了套用某个脚本，牺牲指定版式、原生组件或可编辑性。
使用秀米原生卡片时读 [原生卡片制作](native-cards.md)，按真实条目绑定、组件锚点、原生输入与整组复用推进。
基础生成器是可选工具，不是所有制作路线的必经步骤。已插入秀米原生组件的草稿，禁止再用整篇HTML覆盖；后续在同一浏览器会话内局部编辑。

## 素材选择与快速反馈

先判断题图、章节标题、照片组合或装饰的用途，再搜索并实际看图；素材须与内容、整体风格和固定首尾协调。关键词相近或颜色相似不足以证明适用。优先处理开头、章节标题和主要照片，不要求每段都有装饰。
围绕关键位置做一轮有针对性的搜索，候选足以形成协调方案就试排；未找到合适元素则调整关键词、减少装饰或换制作路线，不无限浏览。
明确参考且方向清楚时直接完成全文；方向不确定且整篇返工代价较高时，用真实文字和照片先做“开头＋一个正文模块”。只有存在两种有意义的不同方向时才给两个短样，不每次强制两套。
先完成整体结构、统一风格和图文顺序，再精修裁图、标题和图文距离。把“太花、太空、不够正式”等反馈落实为具体改动，不用改变硬规范来迎合模糊审美。

## 验收与复用

验收分别回答：硬规范是否满足、用户指定样式和素材是否落实、手机实际效果是否协调。脚本只能证明其覆盖的参数和内容，不能证明用户喜欢。
自动清单验收适用于基础生成器或配有准确内容清单的HTML；原生秀米复杂组件应结合实际组件结构、计算样式和截图逐项验收，不能因脚本不认识组件就破坏组件，也不能报告未执行的自动通过。
记录本篇采用的素材名称、来源位置及用途，便于续改。只有用户明确认可的成稿才作为以后可选样例；模型自评、用户沉默和一次测试成功均不等于认可，不自动变为所有文章的默认模板。

对于用户指定的原生素材，先验证一个模块能插入、编辑、保存复开且保留所需效果，再扩展到全文。切类、搜索或插入后检查实际结果是否变化；连续同态不是“库里没有”，不要继续猜模板ID或要求用户代替完成常规操作。用户只要求效果时，技术路线由执行者决定；明确限制方法时则遵守，不把对结果的授权扩大为发布、购买或清理账号。
