# 自制可编辑HTML的秀米兼容路径

本文限定于当前固定 all-to-xiumi 提交`2f92030687a1ebb891e07b6f3747484456fc8bbb`的样式保留导入路径。它不是秀米全部HTML能力清单，也不保证网站变化后永不出错。原生组件不交给本路径拆平或重新整篇生成。

## 采用的结构

1. 每个独立视觉块用一个**顶层section**，多个块顺序排列。不要用一个大section包住全文；section外的文字、图片不会自动成为样式化组件。
2. 顶层section放背景、边框和块间留白；内部用p承载文字，span/strong/em作必要局部格式，br作有意换行，img作图片。不靠嵌套div/section构造复杂容器。
3. 字号、行高、字距、对齐和缩进写成明确的内联样式；正文参数来自当前规范。标题与装饰按角色设计，不能把普通正文改称装饰来绕过规范。
4. 优先普通单列文档流，让文字随内容自然增高；长标题允许换行。不依赖固定文字高度、绝对定位、flex/grid、CSS变量或外链样式完成保守路径。这些需求不代表不能实现，可转原生结构或单独验证。
5. 一个间距只安排一个负责位置，正文自身margin/padding清楚设置，避免与外层留白叠加。正文侧距按当前规范检查完整祖先链。

最小结构示意（先填入本篇数值；不能把占位稿当成品）：

```html
<section style="background-color:{{主色}};padding:{{标题区留白}};margin:0;">
  <p style="margin:0;font-size:{{标题字号}};line-height:{{标题行高}};color:{{标题颜色}};">{{已确认标题}}</p>
</section>
<section style="padding:{{当前规范的段落留白}};margin:0;">
  <p style="margin:0;font-size:{{正文规定字号}};line-height:{{正文规定行高}};letter-spacing:{{正文规定字距}};text-align:{{正文规定对齐}};text-indent:{{正文规定缩进}};">{{真实正文}}</p>
</section>
```

## 这条导入器的具体限制

- **容器会变形**：内部div/section会被转换为p，容器语义不会保留，甚至可能产生嵌套p供浏览器自动纠正。未知标签没有被删除，不等于它被正确支持。
- **顶层style解析有限**：统一写成`style="..."`，等号两侧不加空格。当前解析按分号拆声明，并忽略box-sizing；内部再使用引号可能截断样式。顶层不要使用带引号的字体名或复杂CSS值；字体可放到文字p上并提供通用回退字体。不依赖border-box抵消固定宽度和padding。
- **字面空格可能压缩**：必须保留全角空格时用`&#12288;`，或按规范使用CSS缩进；不叠加两种缩进，也不靠大量空格定位。
- **图片不是粘进去就持久化**：优先提供可读取的本地原文件，使用上传模式，将图源转换为秀米持久地址。统一写双引号`src="..."`，等号两侧不加空格，当前上传和替换依赖此形式。已有data/blob图源不会在这条样式保留路径自动转为CDN；不要与inline/omit模式混用后声称图片完整。
- **保样式可能降级**：保样式构建失败时，上游会退回基础粘贴。返回布尔值可能只表示正文模型写入，不证明背景、边框和字号都保留。检查日志、实际计算样式和保存后预览。
- **导入会替换整篇组件**：仅用于新稿基础搭建；已有原生卡片或用户人工内容时用局部编辑，不把重新导入当修复按钮。

## 导入前预检

```text
<Python> <技能目录>/scripts/check_layout_source.py <已填妥的HTML文件>
```

预检只读取，不改写文件。退出码含义：
- `0`：未发现已知源文件风险，继续实际制作与检查；不是“兼容通过”。
- `1`：需要针对性判断，例如复杂布局、固定高度。执行者确认是否依赖该特性，改用保守结构／原生组件或只测试相关模块，不一律交给用户处理。
- `2`：先修源文件，例如未填占位项、外部CSS依赖、未闭合标签、漏在section外的内容、图片路径或引号问题。

预检不判断事实、机构规范、审美、账号权限或保存状态，也不能识别所有渲染问题。不要把原生组件导出的复杂HTML送来后，为消除提示而破坏原生结构。

## 按顺序执行

1. 保存`article.html`，另存本篇的完整原文顺序、图片用途与当前格式要求；先运行预检。错误先修，风险由执行者判断，不跳过报告。
2. 复用已连接的driver。只有尚无连接时才按同会话指引启动`scripts/same_session.py`，浏览器与资料目录使用本次已确认选择。
3. 对**新稿**在该交互进程中执行：

   ```python
   url = import_new(driver, html_path, title, checkpoint=task_checkpoint)
   reopen(driver, expected_text=known_body_sentence)
   actual = snapshot(driver)
   preview = capture_saved_preview(driver, preview_path)
   ```

   路径及变量由执行者填入真实值。`known_body_sentence`仅用于等待页面加载，不代替全文核对。已有checkpoint或原生稿件先读记录、核对原稿，不能再次调用新建入口。
4. 对照完整原文和图片清单，检查各类正文及祖先留白的实际值；查看预览的`layout`结果与图片本身。提供专用审计器的机构版本可同时使用该工具，其他机构不能照搬其数值和署名契约。
5. 对不符合要求的位置按下表局部修复，必要时`save(driver)`后再`reopen(driver)`复核。未解决的具体问题保持明确状态，不用“未报错”代替交付结论。

## 保存后检查及修复

| 观察到的问题 | 先核对什么 | 优先处理 |
|---|---|---|
| 本地好看，导入后结构或边框变了 | 是否嵌套容器、依赖外部CSS，是否发生基础粘贴降级 | 拆为独立块或改原生结构；确认背景/边框所在组件，不不断重贴整篇 |
| 图片在当前页可见，复开丢失 | 图源是否仍是本地/data/blob，上传是否真正替换了src | 用本地原件完成上传，核对持久图源和复开加载，不用截图替代应保留的动图 |
| 字改好了，保存后变回去 | 是否只修改了DOM，编辑器是否真正激活 | 真实点击激活后按唯一文本／段落设置选区并输入，再保存复开 |
| 字号合规但留白不对 | 文字、组件及祖先的margin/padding与空段是否叠加 | 修负责留白的那一层，按实际几何间隔验收 |
| 页面宽度正常，部分文字仍看不到 | 长标题或上层裁切，固定宽高与偏移 | 调整容器／换行结构；使用实际文字可见范围检查，不靠缩字硬塞 |
| DOM对比不同，但肉眼正常 | 临时编辑工具条、px转百分比、取样时机 | 退出编辑状态，比较计算样式与实际内容，不直接判为设计丢失 |
| 横滑内容超宽或动画截图不动 | 是否本就是交互区域／截图只是单帧 | 实际滑到末项、观察连续画面；不要把有意交互误报成溢出或静态 |

每次只改变明确出问题的层，保存同一主稿并复核。已知普通结构直接使用；只有引入未验证结构、导入版本变化或出现具体故障时才做最小针对性测试，不要求先收集大量案例。
